# Решение

## Сколько заняло

Около 1,5 часа: экран и работа с данными ~50 минут, разбор чужого кода ~20 минут, поиск, проверка и этот файл ~20 минут.

## Что сделано и что не успел

- Экран «Матчи тура»: загрузка с сервера, список карточек (команды, города, счёт, дата и время в часовом поясе устройства, статус по-русски), состояния загрузки, ошибки (с кнопкой «Повторить») и пустого списка.
- Фильтр Все / Предстоящие / Завершённые, кнопка «Обновить» + pull-to-refresh, подпись «Обновлено N сек назад».
- Поиск по названию клуба (доп. задание из README).
- Исправлены обе жалобы из части 2 (см. ниже).

Не брал: сохранение избранного между запусками — нужно подключать AsyncStorage; вынес в «Что улучшил бы».

## Решения

- **Статусы вне трёх основных.** В «Предстоящие» попадает всё незавершённое: `scheduled`, `live` и `postponed`; завершённым считается только `finished`. Так live-матч (идёт сейчас) и перенесённый не пропадают ни в одном из фильтров. В карточке live дополнительно подсвечен и показывает минуту.
- **Неочевидные случаи в данных:**
  - `startsAt: null` у перенесённого матча — показываем «Дата уточняется»; при сортировке такие матчи уходят в конец списка.
  - `score: null` — показываем «—»; проверка именно на `null`, а не на «пустоту», чтобы счёт 0:0 не превращался в прочерк.
  - Даты приходят в UTC (`...Z`) — выводим через `toLocaleString`, то есть в часовом поясе устройства.
  - Неизвестный статус из будущих версий API показываем как есть, а не прячем.
- Сортировка — хронологическая по дате начала.

## Баги из части 2

1. Звёздочки: избранное проверялось как `Boolean(favorites.indexOf(id))`. `indexOf` возвращает `-1` для отсутствующего id, а `Boolean(-1)` — это `true`: поэтому звёзды горели у всех матчей сразу. Для первого элемента `indexOf` возвращает `0` (это `false`) — избранный матч выглядел невыбранным, и нажатие «гасило» его. Плюс `toggle` мутировал тот же массив (`push`/`splice`) и передавал его же в `setState` — ссылка не менялась, React не перерисовывал, поэтому нажатия срабатывали непредсказуемо. Исправлено: `includes` для проверки и новый массив (`filter`/spread) в `setFavorites`.
2. «Обновлено N сек назад»: `setInterval` замыкался на начальное значение `seconds` (0 → каждую секунду снова 1), а `since` вообще не использовался — поэтому число застывало и не сбрасывалось после обновления. Исправлено: тик обновляет текущее время, секунды считаются как `now − since`, эффект перезапускается при смене `since` и очищает интервал при размонтировании.

## Как я использовал ИИ

Claude Code (агент) как основной инструмент: разбор задания и данных, каркас экрана, фиксы. Примеры неверных или неполных мест, которые заметил и поправил:
- Отображение счёта напрашивается как `score?.home || '—'` — на матче 0:0 это даёт прочерк вместо счёта. Проверил на данных (m2) и заменил на явную проверку `score === null`.
- Вариант «live-матчи показывать только во вкладке Все» терял бы их в обоих фильтрах — отнёс live к «Предстоящим» и объяснил здесь.
- В счётчике «Обновлено» важно считать секунды от `since`, а не накапливать их от нуля — иначе после «Обновить» число не сбросится.

Проверка результата: `npx tsc --noEmit`, запуск `npm run web` в браузере, ручной прогон состояний — загрузка, ошибка и «Повторить», пустой фильтр, звёздочки (включая первый и последний матч), счётчик после «Обновить».

## Что улучшил бы, будь ещё 2 часа

- Сохранение избранного между запусками (AsyncStorage) и автообновление данных раз в минуту.
- Юнит-тесты на фильтр и форматирование — логика уже вынесена в чистые функции `src/utils/matches.ts`.
- Группировку списка по дням и скелетоны вместо спиннера.
